## 1. Detect 头在做什么

### Q：Detect 主要做了什么工作？

可以把它看成「把 Neck 的多尺度特征，变成可训练、可解码的检测张量」的薄头，主要四件事：

1. **记住先验**：三个尺度的步长（8 / 16 / 32），以及每个尺度上 3 个锚框的宽高。
2. **每个尺度一个 1×1 卷积**：把通道映射成「锚框个数 ×（4 个几何量 + 1 个物体分数 + 类别数）」。
3. **初始化偏置**：物体分数按大约「每图若干目标」的密度设；多类时再设类别先验，减轻训练初期乱飞。
4. **训练 / 推理分流**：
   - 训练：输出三个尺度的原始预测，交给损失；
   - 推理：按统一公式解码成像素框，拼成大候选表，外面再接 NMS。

它**不算损失**，也**不做 NMS**。分工是：Backbone / Neck 提特征 → Detect 出候选 → Loss 管训练 → NMS 出最终框。

## 2. 多尺度如何变成结果框

### Q：不同输出的检测头最后是怎么输出结果框的？

三个尺度对应输入上每隔 **8 / 16 / 32** 像素一个格子：

| 尺度 | 步长 | 640 输入时大致网格 | 更适合 |
|------|------|-------------------|--------|
| 浅 / 细 | 8 | 约 80×80 | 小目标 |
| 中 | 16 | 约 40×40 | 中目标 |
| 深 / 粗 | 32 | 约 20×20 | 大目标 |

每个格子挂 **3 个锚框**，每个锚框预测：中心偏移、宽高缩放、物体分数、各类别分数。

**推理时**解码成整图像素框（中心 + 宽高），三个尺度拼成一张大候选表（640 输入大约两万多个），再置信度过滤 + NMS。

**训练时**一般不在头里解成最终框，保留原始预测，在损失里用同一套公式解码再和真值比。

### Q：为什么浅 / 细尺度对应小目标？

两层原因叠在一起：

1. **分辨率与感受野**：步长 8 的特征图更大，每个格子大约对应原图 8×8，细节多、定位细，适合小目标；步长 32 每个格子约 32×32，语义强但更糊，适合大目标。
2. **锚框按尺度分好了**：细尺度挂小宽高先验，粗尺度挂大先验；训练时还用宽高比过滤，小真值更容易匹配细尺度。

## 3. 锚框（Anchor）

### Q：锚框是怎么设置的？

官方 COCO、输入约 640 时，常用 **9 组像素宽高先验**，按大小分到三个检测尺度，每尺度 3 个。本仓库默认写在 `yolov5.py` 的 `DEFAULT_ANCHORS` 中，大致是：

- 细尺度：偏小的框；
- 中尺度：中等框；
- 粗尺度：大框（可到几百像素）。

来源：在 COCO 真值框上聚类（如 k-means），再按面积分到三层。网络学的是「在这个先验附近怎么挪中心、怎么改宽高」，而不是从零猜任意形状。自己数据集可重跑 autoanchor；不改也能训，匹配率可能差一些。

### Q：一共才九个 anchor 吗？还是三种尺度？锚框落在哪个像素位置上？

要分清三件事：

1. **形状模板：9 种**  
   「9 个 anchor」通常指 9 种先验宽高，不是整张图只有 9 个框。

2. **挂到图上的数量：非常多**  
   每个尺度的每个格子，都挂该尺度的 3 种形状。640 输入大约：
   - 细：80×80×3 ≈ 19200  
   - 中：40×40×3 ≈ 4800  
   - 粗：20×20×3 ≈ 1200  
   合计约两万多个「格子 × 形状」候选。

3. **位置：不是钉在几个固定像素点**  
   - 特征图铺满整图成网格；
   - **每个格子的中心**（映射回原图像素）是该格子上所有锚框的默认中心；
   - 同一格子上 3 个锚框中心相同，只是宽高不同；
   - 网络再学中心相对格子的偏移、宽高相对先验的缩放。

一句话：**9 种模板 × 所有格子 = 海量候选；先验默认位置是格子中心。**

## 4. 预测向量各分量含义与解码

### Q：每个 Anchor 位置输出长度为 class_num + 5 的向量，`(tx, ty, tw, th, tobj, tcls...)` 分别是什么？

| 分量 | 含义 | 解码后 |
|------|------|--------|
| `tx`, `ty` | 相对本格子中心的位置偏移（原始 logits） | 原图中心 `(cx, cy)` |
| `tw`, `th` | 相对本锚框宽高的缩放（原始 logits） | 原图宽高 `(w, h)` |
| `tobj` | 这里有没有物体 | 物体置信度（常再 sigmoid） |
| `tcls...` | 各类别分数（`class_num` 维） | 各类概率 |

前 4 维管几何，第 5 维管「有没有」，后面管「是什么」。最终画框用解码后的中心与宽高；NMS 分数通常由物体分数与类别分数组合。

### Q：为什么是 `sigmoid × 2 − 0.5`，大约落在 −0.5～1.5？

`sigmoid` 把输出压到约 (0, 1)，再 `×2 − 0.5`：

| sigmoid | 变换后 |
|---------|--------|
| 0 | −0.5 |
| 0.5 | 0.5 |
| 1 | 1.5 |

用意：

- 默认中心落在本格子内（0～1 对应格子内；约 0.5 为偏中性位置）；
- −0.5～0、1～1.5 允许略偏到相邻格子，方便真值贴在格子边界时仍好回归；
- 与训练时「中心格 + 邻居格」正样本分配配套。这是 YOLOv5 相对更早版本改过的中心公式。

### Q：为什么对 `tw`、`th` 做 sigmoid，再乘 2，再平方？是不是既能缩小也能放大到约四倍？

令 `s = sigmoid(·)`，缩放系数是 `(2s)²`：

| s | (2s)² | 相对锚框 |
|---|-------|----------|
| →0 | →0 | 可缩得很小 |
| 0.5 | **1** | 约等于锚框（中性点） |
| →1 | →**4** | 大约最多放大到 4 倍 |

因此可以比先验更小或更大，但大致封顶约 4 倍，避免宽高爆炸。特别大的目标主要靠粗尺度上更大的锚框匹配，而不是指望细尺度把小锚框放大几十倍。

### Q：算 loss 时，是不是也要把标签变成中心偏移和 wh 缩放？

**要对齐到格子坐标系，但通常不是先反解成 `tx,ty,tw,th` 再和原始 logits 比。**

常见做法（本仓库也是）：

1. **标签**：归一化中心/宽高 → 乘网格大小 → 格子单位下的中心与宽高 → 分到格子与锚框；正样本上的框目标一般是「相对该格子的中心偏移 + 宽高（格子单位）」。
2. **预测**：正样本位置的原始输出，用与推理同一套公式解码成格子单位下的预测框。
3. **比较**：在解码后的框空间算 CIoU，而不是在四个未解码 logits 上直接 L1/L2。

物体分数、类别在正/负样本位置上与对应目标比较。

## 5. 损失函数是什么

### Q：YOLOv5 的 loss 是什么？

三项加权求和（总损失再乘 batch 大小）：

| 项 | 形式 | 作用 |
|----|------|------|
| **框回归** | `1 − CIoU` | 只在正样本上；预测框与真值框的重叠 + 中心距 + 宽高比 |
| **目标性** | BCEWithLogits | 所有格子×锚框；正样本目标为软 CIoU（切断梯度、≥0），负样本为 0 |
| **分类** | BCEWithLogits（多类） | 只在正样本上；单类时常跳过或权重极小 |

额外要点：

- 三尺度目标性再乘平衡权重（常见约 4.0 / 1.0 / 0.4，细尺度更大）；
- 增益大致：框约 0.05、目标性约 1、分类约 0.5，并按尺度个数、类别数相对 80、输入边长相对 640 等缩放。

## 6. 正样本分配与多尺度 / 多分类

### Q：如果 GT「偏中尺度」，其他尺度的预测还算 loss 吗？

**不会先锁死「只能在中尺度」。** 每个尺度独立做匹配。

| 损失项 | 行为 |
|--------|------|
| 框回归 | 仅正样本；谁锚框宽高比过关、谁分到格子，谁就算 |
| 分类 | 同上（多类时） |
| 目标性 | **三个尺度都算整张特征图**；没匹配上的尺度把该 GT 相关位置当背景压物体分数 |

一个 GT 可以在多个尺度同时成为正样本；也可以只在一个尺度匹配上。细/粗若比例过滤全挂，则不算该 GT 的框/分类，但目标性仍在算。

### Q：多分类时 loss 怎么处理？

- 每个正样本位置有 `类别数` 维分数；真值做成 one-hot（真类为 1）。
- 用 **各类独立的 BCEWithLogits**（多标签风格），不是 Softmax 交叉熵。
- **只在正样本上算分类**；背景不算分类，靠目标性压下去。
- `类别数 == 1` 时可跳过分类项。
- 分类增益常按「当前类数 / 80」缩放。推理时各类常 sigmoid，再与物体分数组合进 NMS。

## 7. 计算 Loss 的完整流程

### Q：从标签变换、匹配到三项损失，完整流程是什么？

#### 总览

```text
真值表 + 三尺度原始预测
        │
        ▼
对每个尺度：真值 → 格子坐标 → 按锚框宽高比过滤 → 分到中心格及邻居
        │
        ▼
正样本清单：(图编号, 锚框编号, 格子行/列) + 框目标 + 类别 + 用到的锚框
        │
        ▼
对每个尺度：
  · 正样本：解码预测框 ↔ 框目标 → CIoU → 框损失；物体目标=软 CIoU；多类再算分类
  · 全图：物体分数 BCE（正样本用软目标，其余为 0）
        │
        ▼
三项乘增益后相加，再 × batch 大小 → 总损失
```

#### 第 0 步：两边输入

- **标签**：每行 = 图编号、类别、中心 x/y、宽/高（相对整图归一化到 0～1）。
- **预测**：三尺度原始输出（每格每锚框一截向量），尚未变成像素框。

#### 第 1 步：锚框换成格子单位

像素锚框 ÷ 该尺度步长 → 与真值宽高在同一「格子单位」下比较、解码。

#### 第 2 步：每个尺度独立分配正样本

1. 真值中心/宽高 × 本尺度网格宽高 → 格子坐标。  
2. 每个目标与本尺度 3 个锚框先两两配对。  
3. **宽高比过滤**：`max(比值, 1/比值)` 是否小于阈值（默认约 4）；不过关丢弃。  
4. **中心格 + 邻居**：中心所在格必选；靠近左/右/上/下边界时再分给邻居（约 0.5 规则），每尺度每匹配锚框大约 1～3 个正格子。  
5. 记录正样本位置、相对该格子的框目标、类别、所用锚框。

#### 第 3 步：每个尺度算损失

1. 建物体目标图，先全 0。  
2. 有正样本时：按与推理同一套公式把预测解码成格子单位框 → 与框目标算 CIoU → 累加 `1−CIoU`；该处物体目标写成软 CIoU；多类则 one-hot + BCE。  
3. 对该尺度所有位置的物体分数与物体目标图做 BCE，再乘该尺度平衡权重。

#### 第 4 步：汇总

框 / 目标性 / 分类分别乘增益后相加，再乘 batch 大小得到总损失。

#### 小例子

一个中等大小真值：细尺度可能比例全挂 → 无正样本，仍算背景目标性；中尺度常匹配上 → 算框（和分类）；粗尺度视比例而定。最后三尺度目标性 + 各项增益汇总反传。

#### 常见误解

| 误解 | 实际 |
|------|------|
| 先判定「中尺度 GT」再只在中尺度算 | 每尺度独立匹配；可多尺度同时为正 |
| 标签必须反解成 tx… 再和 logits 比 | 标签→格子框；预测→解码成框；比 CIoU |
| 没匹配上的尺度完全不算 loss | 框/分类可不算；目标性仍对全图算 |
| 分类对所有格子算 | 只对正样本；背景靠目标性 |
